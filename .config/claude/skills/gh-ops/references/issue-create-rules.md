# Issue の作成

テンプレートに沿って本文を書き、`gh issue create` で Issue を作る。

## 書く内容

- タイトルは解きたい課題の言葉で書く。「script を作る」「設定を足す」のような手段をタイトルにしない
- 本文には課題と目的だけを書き、設計や手段 (作るもの、変えるファイル、取る方法) を書かない
- 前の Issue や外部の資料への参照は、課題か経緯の文の中に書く。親の Issue は本文に書かず、`--parent` で示す

## テンプレート

`{...}` を中身に置き換える。

- 課題は必須で、今起きていることと、それで困ることを書く
- 目的は必須で、課題が解けたときの状態を書く
- 経緯は、試して捨てた案や置き換えた Issue があるときだけ 1、2 行で書く。無いときは見出しごと消す

```markdown
## 課題

{problem}

## 目的

{goal}

## 経緯

{history}
```

## 作成

```bash
gh issue create --title '<タイトル>' --body-file - <<'EOF'
<テンプレートに沿って書いた本文>
EOF
```

リポジトリ、ラベル、担当者、プロジェクトを指定するときと、親の Issue の子として作るときは、`gh` のフラグ `--repo`、`--label`、`--assignee`、`--project`、`--parent` をそのまま使う。
